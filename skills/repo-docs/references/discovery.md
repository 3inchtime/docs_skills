# 从仓库取得可解释的事实

## 调查顺序

1. 读取仓库规则、已有文档站和工作区状态。
2. 检查依赖、锁文件、任务脚本、CI、容器与运行配置。
3. 列出 HTTP/RPC、CLI、消费者、任务、回调和启动钩子及注册位置。
4. 按业务责任、数据所有权和状态划分模块，映射每个入口。
5. 从入口追到可观察结果，再补跨模块业务链路。
6. 对照测试、迁移、配置和业务材料，处理冲突并记录缺口。

## inventory.py 的范围

脚本读取 Git 跟踪及未忽略的文件名，统计语言线索、配置路径和入口候选；记录 commit、分支与工作区状态。它不读取业务文件内容，不运行项目命令，不将候选文件认定为真实入口。

无 Git 时使用目录遍历并明确标注。超过 `--max-files` 时输出 `truncated` 和总数；不要把截断结果称为全仓库调查。文件名也可能包含内部业务信息，只在授权位置保存。

## 入口与可达性

读取路由注册、消费者注册、依赖注入和功能开关。存在同名函数不证明运行时可达。依赖生成代码时检查生成输入和构建过程。

记录触发者、注册位置、入口符号、输入约束、权限、配置与责任模块。公共库通过真实使用者说明输入到输出的处理；声明集合解释实际加载或使用过程。

## 逐步追踪

| 关注点 | 要读的内容 |
| --- | --- |
| 业务判断 | 条件、枚举、单位、精度、日期边界 |
| 数据变化 | 查询过滤、更新字段、约束、事务开始和提交 |
| 异步边界 | 发送点、消费点、确认时机、失败处理和开关 |
| 重试 | 执行者、错误、总尝试次数或额外次数、间隔和终态 |
| 重复执行 | 幂等键、唯一约束、去重范围、已有记录处理 |
| 外部调用 | 契约、超时、错误映射和本地状态 |
| 恢复 | 回滚、补偿、清理、人工入口或未实现部分 |

不套理想架构补不存在的分支。外部系统内部不可见时在契约处止步。

## 证据分类

- `source/read`：读过指定实现或配置，不等同生产运行。
- `test/read`：读过测试断言；实际运行后才使用 `test/executed` 并附结果。
- `runtime/observed`：记录环境、输入、时间和可复查材料。
- `business/confirmed`：记录业务资料或确认来源及适用范围。

旧文档与代码冲突时，分别写当前实现与旧记载。实现不能单独证明行业规则或历史设计动机。

## 命令与首次操作

记录命令来源、目录、环境、执行状态、结果和未执行原因。配置示例使用名称和占位值，不复制真实密钥。

首次运行教程应有真实业务输入、预期响应和数据变化。进程启动或端口监听不足以证明业务跑通。

# 仓库交接文档

把当前代码写成新人可以理解、验证并继续修改的手册。默认用中文，保留代码符号原名；用户指定其他语言时遵从用户。

## 快速开始

1. 确认目标仓库、代码基线和输出目录。已有上下文足够时直接开始，不重复询问已给出的信息。
2. 读取仓库自己的 `AGENTS.md`、贡献规则和现有文档。复用文档站、构建命令与命名约定。
3. 运行本技能的 `scripts/inventory.py --repo <仓库> --output <调查结果.json>`，把输出作为线索。继续打开真实入口、注册、配置、实现与测试。
4. 建立模块与入口清单，完成一个真实模块的完整样板，再覆盖整个约定范围。
5. 交付正文、每模块流程、业务词典、证据索引、维护规则与真实验证记录。不要以大纲或样板代替全量交付。

## 阶段与交接产物

### 1. 确定基线和范围

记录 commit、分支、未提交改动和调查范围。没有 Git 元数据时记录可识别的文件快照，不编造 SHA。为每个真实入口分配模块；模块围绕业务职责、数据和状态划分，不机械等同于目录。

产出调查清单、命令表、模块表、排除项及理由。脚本只提供候选路径，不证明模块边界、调用链或部署事实。

### 2. 沿入口建立证据

追踪输入、校验、业务判断、读写、状态变化、外部调用和最终结果。检查重要异常、重试、事务、幂等和恢复行为；不存在的能力不要补进图中。

给关键规则和图节点关联文件、符号、配置、测试或业务资料。将静态阅读、测试执行、环境观察和业务确认分别记录，区分默认配置与环境覆盖。

产出逐步流程、业务规则表、证据条目和具体待确认事项。

### 3. 写出可独立阅读的解释

使用模块模板并按实际复杂度裁剪。先说明业务任务，再按执行顺序解释实现，最后提供修改和验证方法。每个关键动作说明主体、条件和结果。简单模块可以合并小节；调查检查项不必全部变成正文标题。

提供一条完整新人路线：环境和版本 → 配置 → 迁移与最小数据 → 启动顺序 → 一次真实业务操作 → 响应及数据变化。命令取自仓库；外部条件不足时记录具体阻塞点。

补充至少一条有代表性的跨模块链路。区分请求接收与业务完成，同步或异步关系以代码为准。

产出完整模块页、首次运行教程、开发任务指南和跨模块流程说明。

### 4. 加入流程、词典和页面

如果相关技能可用，按阶段调用：

- `repo-diagrams`：根据证据创建 `.mmd` 和 SVG，核对关键分支。
- `business-glossary`：解释业务词、适用范围、例子和代码映射。
- `repo-docs-site`：将已核对的内容放入现有站点或 Starlight，增加必要交互。
- `repo-docs-review`：检查结构、语义、读者理解与变更影响。

每个技能接收自己的输入和输出位置，只在相应阶段加载。缺少专用技能时按以下最低要求继续，说明具体缺少的工具，不假装已调用。

最低要求：每模块有真实执行流程；需要时补时序或状态图；图旁有文字步骤；词典只收业务词；页面可导航和搜索；正文和图源可持续维护。

优先采用 Markdown/MDX + Mermaid 图源。已有文档站继续使用；没有时采用 Starlight，并在构建时生成 SVG。单文件 HTML 可作为摘要，完整站点交付全部资源和明确预览方式。

### 5. 分开核对事实和理解

让代码审查者拿文档和源码核对关键行为。让独立读者只拿文档和任务，回答入口、规则、状态变化、失败、修改位置、验证方式和业务词含义；不要给读者作者推理或预期答案。

没有独立代理时做明确标注的自查，不称为独立读者验收。修复实际缺口后定向复查。

自动构建、路径检查和图源解析不证明业务语义正确。重大当前行为未查清时保留具体阻塞项，不标为完全核验。

### 6. 建立更新规则

维护 `docs-map.json`，关联源码、配置、入口、模块、正文、图源和词条。将接口、事件、规则、状态、迁移和配置变化作为复核触发项。

代码改动后检查受影响页和上下游，在同一个 PR 更新。固定 commit 链接保存历史依据，变更检查提示新影响；指纹和路径匹配只提供候选线索。

## 写作要求

- 已核实行为直接写，用具体条件替代“必要时”“视情况”。
- 将真实未知列成问题，写明缺什么、影响什么，不给每句话加笼统限定。
- 分开当前实现、已有历史决策、解释性推断和未来建议；无记录时不编造动机。
- 将“优化、完善、合理、灵活、稳定”等词改成对象、动作与可观察结果。
- 真实缺陷按现状说明，建议另列；保持必要边界，不用武断语气制造确定性。
- 边界说明必须影响当前操作、结果判断或继续开发。省略与实际调用无关的理论风险，不逐项罗列所有不存在的能力；同一限制在合适位置解释一次。
- 普通技术词不填充业务词典，同一业务概念统一命名并链接定义。

## 完成条件

对照清单检查全部约定模块、关键入口和每模块流程，记录例外及理由。交付完整内容、图源、证据与术语映射、站点构建方式、更新规则和验证记录。

最终说明完成内容、实际检查、结果和剩余具体问题。用户已授权的文档生成与必要构建自主完成；超出任务授权的外部发布或业务变更另行处理。

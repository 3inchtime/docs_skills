## 1. 收录与排除

以理解业务行为为准，不以词语看起来是否专业为准。

| 候选词类型 | 处理 |
| --- | --- |
| 行业业务概念 | 仓库确实使用时收录 |
| 公司内部规则或业务缩写 | 收录，说明正式名称与适用产品 |
| 普通词的特殊业务含义 | 收录，写清本系统口径 |
| 业务枚举或事件简称 | 收录或映射到已有概念，避免重复 |
| API、HTTP、JWT、Redis 等一般技术名称 | 不作为业务词典填充项 |
| 与仓库无关的行业词 | 排除，不能因用户举过例子就默认存在 |

一个缩写可能有多种展开方式，必须查它在当前实现中的使用。别名合并后保留可搜索性；有实质含义差异的词不要只为减少词条而合并。

## 2. 定义的两层证据

### 业务或行业定义

回答概念在什么语境下是什么意思。来源可以是项目产品规格、合同条款、业务规则文件、已有术语表，或行业原始资料。记录市场、产品范围和需要时的适用日期。

### 本系统的实际用法

回答它在当前系统中怎样表示、计算和影响流程。来源包括真实字段、枚举、规则判断、测试、配置和业务确认记录。代码可证明当前实现，不能自行证明未记录的业务设计意图。

例如，某概念理论上允许多种数量单位，当前代码可能只接受整数。词条应分别写出概念范围和当前输入约束。发现差异时注明差异，不把规范要求写成系统已实现的能力。

## 3. 数据格式

```json
{
  "schema_version": 1,
  "terms": [
    {
      "id": "<稳定的英文标识>",
      "name": "<业务名称>",
      "aliases": ["<英文、缩写或内部别名>"],
      "definition": "<一句话业务定义>",
      "scope": "<市场、产品或业务规则范围>",
      "project_meaning": "<本系统实际用法或具体待确认问题>",
      "example": "<有前提、单位与结果的业务例子>",
      "code_refs": [
        {"path": "<仓库相对路径>", "symbol": "<已读取的符号>"}
      ],
      "sources": [
        {"title": "<业务资料标题>", "path": "<仓库相对资料路径>"},
        {"title": "<外部原始资料标题>", "url": "<https链接>"}
      ],
      "status": "pending"
    }
  ]
}
```

`id`、`name`、`definition`、`scope`、`project_meaning`、`example` 使用字符串；`aliases`、`code_refs`、`sources` 使用数组。`sources` 中至少提供 `url` 或 `path`，不要求公司内部概念有公开网页来源。`symbol` 可省略；路径指向实际存在的材料。

`status` 含义：

- `verified`：定义与项目用法已获得相应依据，包含来源和代码映射。它不自动表示相关测试已执行或生产环境已验证。
- `inferred`：根据代码与资料提出的解释，写明推断依据和范围，尚不能当作已确认的正式口径。
- `pending`：含义、范围或映射仍有具体问题待解决，在 `project_meaning` 或附加问题记录中说明。

可以增加 `module_ids`、`not_to_confuse_with`、`business_effect`、`owner`、`verified_commit`、`verified_at` 等字段。只填写真实取得的信息，不为凑字段造值。

模块在 `docs-map.json` 中使用 `modules[].terms` 字符串数组关联词条，例如 `"terms": ["settlement-date"]`；`glossary.json` 顶层的 `terms` 则是完整词条对象数组。按 ID 连接两者，不把完整词条复制进模块映射。页面内解释和完整词典从同一数据来源生成，避免各页拷贝后出现不同定义。

## 4. 例子与边界

例子应使用容易核算的输入，并明确单位、适用范围和假设。需要时间窗口、时区、数量精度、货币或舍入方式时写出来。例子如果只是帮助理解，而不是执行过的测试，标为说明性例子。

### 香港 odd lot 与 fractional share

香港交易所的相关说明将 odd lot 描述为少于一个完整买卖单位的证券数量。若某证券每手为 100 股，持有 35 股属于不足一手的例子。

Investor.gov 的 fractional share 定义指少于一整股的股份，例如 0.25 股。

这两个定义使用不同计量边界。不能把“少于一手”写成“少于一股”，也不能从中文简称推断仓库采用哪一种含义。这里仅说明术语核对方法，不表示目标仓库属于证券业务。

### 拆股或合股等业务

只有目标代码涉及该业务时才收录。继续查事件类型、数量比例、单位、成本调整、舍入和剩余权益等实际规则；不能从一个 `Split` 类名生成整套看似完整的财务处理说明。

## 5. 核验与维护

让业务审阅者核对定义、语境和规则，让代码审阅者核对字段、枚举与实现关联。独立读者回答：

1. 这个词是什么意思，适用于什么范围？
2. 它和一个相邻概念有什么区别？
3. 例子中的输入为什么产生这个结果？
4. 它影响哪个模块、字段或业务流程？

字段改名、规则改变、产品范围改变或术语新增时更新词条、例子与引用。旧 ID 若已被页面引用，应保留别名或迁移映射；先检查引用，再删除无效词条。

## 选择与版本

先查看仓库现有文档入口、任务命令、包管理器、运行版本和部署方式。

| 仓库状况 | 处理方式 |
| --- | --- |
| 已有 Starlight、VitePress 或 Docusaurus | 复用站点；按当前安装版本的官方文档适配组件 |
| 只有少量 Markdown | 保留可用正文，新增文档站入口和导航 |
| 没有文档站 | 默认 Starlight + Markdown/MDX；按官方入门流程建立工程 |
| 只需离线传阅一份说明 | 输出自包含摘要，同时保留可维护的内容来源 |

不要把第三方技能内的框架版本、网上过时片段或主站的预览版本直接写入依赖清单。确定实施时的稳定版本和兼容运行环境，生成并提交 lockfile。之后从 lockfile 安装，而不是每次重新选择最新版本。

本技能不附带硬编码依赖版本的 `package.json`，以免在不同目标仓库中创建第二套不兼容工具链。

## 源文件和生成物

以下是新工程的建议位置，不是对目标仓库目录的断言。

| 位置 | 内容 | 维护方式 |
| --- | --- | --- |
| `docs-site/src/content/docs/` | Markdown/MDX 正文 | 人与代理评审修改 |
| `docs-site/src/components/` | 可复用组件 | 组件接口稳定，按需改进 |
| `docs-site/src/data/` | 业务词典、说明元数据、证据索引 | 共享定义只维护一份 |
| `docs-site/diagrams/` | `.mmd` 图源 | 修改源图并重新生成 |
| `docs-site/public/generated/` | SVG 等生成物 | 构建工具产出 |
| `docs-map.json` | 模块到源码、页面、图和词条的映射 | 跟随业务变更核对 |
| 文档站现有构建输出目录 | HTML、样式、脚本和搜索索引 | 按实际配置生成 |

不同时把手改 SVG 和 Mermaid 当作同一流程的权威来源。手工绘制的专门 SVG 需要保存可编辑源或生成代码，并说明它与业务模型的关系。

## 从样板到全量

样板要包括完整内容和真实依赖，而不是只有一个漂亮首页。

1. 选择已完成代码调查的代表模块。
2. 使用具体业务例子说明输入、动作和输出。
3. 显示至少一条关键条件或失败路径。
4. 引用已生成图，并把文字步骤放在正常文档流内。
5. 接入真实源码链接与代码版本。
6. 加入一个相关业务词，并链接词典。
7. 构建后搜索业务名称、别名与必要代码符号。
8. 测试至少一项实际阅读任务和一个关键交互。
9. 修复模板与构建问题，再按模块清单扩展。

样板完成不是终点。完成用户约定范围中的所有模块；对确实无法核实的内容列出具体缺口。

## 信息架构

按新同事的任务提供入口：

- **理解系统**：业务目标、对象、系统边界、模块地图、跨模块主线。
- **运行业务**：依赖版本、配置、迁移、最小数据、启动顺序、请求和可观察结果。
- **修改系统**：真实扩展任务、需要修改的位置、业务约束和验证方法。
- **查阅与排障**：模块参考、接口、事件、状态、配置、日志和恢复方式。
- **业务词典**：作为最后一个主要章节，并被正文中的词语链接引用。

逐模块页面解释局部行为，跨模块流程解释一次业务如何最终完成。明确同步返回与异步完成的关系；没有异步处理时按同步实现描述。

页面顶部简要说明这页回答的问题和代码基线。页面主体先解释行为，证据区域再提供文件、符号与验证记录。让关键限制保持可见，避免依靠悬停才获得必要条件。

## 构建接线

先从项目任务脚本确定现有命令，再新增必要的文档任务。下列是任务顺序，不是假定仓库已经存在的命令：

1. 检查模块映射与内容引用。
2. 用选定版本的 Mermaid CLI 渲染所有需要发布的 `.mmd`。
3. 只有图形阶段全部成功，才继续构建站点和搜索索引。
4. 检查构建后的链接、资源、页面与搜索。

Mermaid 编译失败时让整个文档任务失败；清楚报告出错源文件。不要因为生成目录中恰好有旧 SVG，就继续报告构建成功。

Starlight 支持 MDX 中导入组件；Mermaid 不是默认 Markdown 就能渲染的语法。可选择额外集成，或采用这里的预生成 SVG 方式。后者便于在构建时检查图形并控制版本。

本技能的原生 HTML 组件可通过项目现有布局加载 CSS 与脚本，再在 MDX 组件中输出对应 HTML 结构。为自定义组件使用独立类名；与 Starlight 正文默认样式冲突时按官方说明使用 `not-content` 外层。不要直接把完整 HTML 文档的 `<html>` 或 `<head>` 粘入 MDX 正文。

资源链接需适配站点配置的 base 路径。将示例中的相对文件路径换成项目内真实资产路径，验证部署子路径下仍可访问。源码链接固定到核验 commit，并另行明确提供当前分支导航时的含义。

## 离线与打印

完整站点离线包应包含页面、样式、脚本、图、字体和搜索索引，并提供实际验证过的本地 HTTP 预览命令。检查断网后的跨页导航和业务词搜索。

自包含摘要将必要 CSS、脚本和 SVG 内联。它可以省略整站搜索，但应明确采用浏览器页面查找或目录导航。避免把一个页面的离线能力扩大成整个站点的离线保证。

打印时展示全图、全部步骤、关键规则与来源。展开必要折叠内容，避免输出只含交互当前状态。PDF 是否清晰需要实际渲染检查，不能从 CSS 里存在 `@media print` 推断已经合格。

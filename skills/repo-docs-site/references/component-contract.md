# 流程逐项说明组件

## 接口与能力

`flow-reader.js` 注册 `<repo-flow-reader>`。组件接收页面中已经存在的 HTML，不请求网络，不解析 Mermaid，不生成业务分支。

它提供上一项、下一项和按标题选取说明的按钮。完整 SVG 与全部说明始终可见；选取仅改变说明卡片边框和当前项标识。它不高亮 SVG 内部节点，也不代表一次业务执行模拟。

| HTML 字段 | 约定 |
| --- | --- |
| `<repo-flow-reader>` | 一张流程及其说明的外层容器 |
| `data-flow-controls` | 操作区；源 HTML 中带 `hidden`，脚本成功初始化后显示 |
| `data-flow-prev` / `data-flow-next` | 上一项和下一项按钮 |
| `data-flow-status` | `role="status"` 的当前位置说明 |
| `data-flow-step` | 一项说明的容器；保留在正文中以支持搜索、打印和无脚本阅读 |
| `data-node-id` | 与维护源图相同的稳定节点 ID，不表示代码行号 |
| `data-flow-select` | 当前说明的标题按钮；源 HTML 中带 `disabled`，初始化后启用，无脚本时作为可读标题 |

外层必须有可访问名称，例如 `aria-labelledby` 指向图标题。页面内标题和锚点 ID 唯一。组件不读取任意 `data-*` 字段为可执行代码。

## 说明数据

由代码调查阶段提供以下内容，再渲染为 HTML：

```json
{
  "node_id": "validate_range",
  "title": "校验日期范围",
  "summary": "填入已核实的条件、动作和结果。",
  "input": "填入这一步的业务输入。",
  "output": "填入这一步的可观察结果。",
  "evidence_ids": ["填入真实证据标识"]
}
```

上面是字段示意；交付真实模块时替换全部说明占位值。证据引用通过项目的证据索引解析成文件、符号、配置或测试链接，不在组件中臆造路径。

说明项的列表顺序用于阅读，不能替代图中的边和条件。默认拓扑仍在 `.mmd` 中。若需要“成功/失败路径切换”，由唯一流程模型生成候选路径；不要在组件代码中另写手工业务判断。

## 集成步骤

1. 将 `assets/flow-reader.js` 和 `assets/flow-reader.css` 复制到项目的组件或静态资源目录。
2. 根据当前站点的资源加载方式引入这两个文件；确认 base 路径和缓存策略。
3. 把示例中的 `<repo-flow-reader>` 结构改造成项目的组件模板。
4. 将模块图嵌入其中；SVG 使用图片时提供有信息量的 alt，内联时提供 title/desc。
5. 从已核对的说明元数据输出全部说明，使用相同节点 ID。
6. 页面加载后测试两个独立实例，确认按钮只影响所属组件。

不能直接把一份包含 `<html>`、`<head>`、`<body>` 的示例文档嵌入 MDX。应抽取容器结构，并在站点布局或组件中加载资产。

## 单文件导出

`build_offline.py` 将以下两个准确标记替换为组件 CSS 和脚本：

```html
<link rel="stylesheet" href="flow-reader.css" data-flow-inline="style">
<script src="flow-reader.js" defer data-flow-inline="script"></script>
```

标记各出现一次才执行。默认模板使用内联 SVG，导出文件不再引用这两个外部资产。

```bash
python3 <skill-dir>/scripts/build_offline.py \
  --template <project>/summary-template.html \
  --output <project>/summary.html
```

脚本只内联随技能提供的这两项资源，不会抓取图片、字体或其他页面资源。自定义模板含其他资源时，应内联或打包它们并另外验证；不能仅凭命令成功宣称完整离线可用。已有输出默认拒绝覆盖；明确需要替换时使用 `--force`。

## 页面验收

| 检查 | 实际操作 | 记录内容 |
| --- | --- | --- |
| 基本阅读 | 读完整图与文字，找出真实条件、失败结果和代码位置 | 读者找不到或误解的具体内容 |
| 键盘 | Tab 到按钮，Enter/Space 选取，走到首尾 | 焦点、禁用状态、读屏位置说明 |
| 多实例 | 同页放两个流程，分别切换 | 是否互相干扰 |
| 无脚本 | 禁用 JavaScript 后重新载入 | 全图与全部文字仍可见，操作区保持隐藏 |
| 窄屏 | 约 390px 宽度检查 | 正文无横向溢出；大图在自身容器内滚动 |
| 打印 | 打开打印预览 | 全部步骤与完整图保留，按钮隐藏 |
| 搜索 | 在构建产物里搜索关键业务条件和术语 | 搜索能找到正文，而非仅找到图标题 |

`node --check` 仅验证 JavaScript 语法。HTML 解析只能检查结构。两者不能代替浏览器布局、可访问性或业务语义核验。环境阻止浏览器时记录这个具体限制，不绕过环境访问控制。

## 视觉技能的边界

`visual-explainer` 可用于某个已核验机制的独立图解，使用它自身的渲染检查。将其结果迁入文档站时仍按项目组件接口适配并重新验收。它的单页默认和图为主的表达不应删掉模块必要的条件、异常、源码导航和修改指南。

# 编译 Mermaid 图源

## 前置条件

- Python 3.10 或更新版本；脚本只使用标准库。
- 已安装并由项目锁定版本的 Mermaid CLI，命令通常为 `mmdc`。
- Mermaid CLI 所需的浏览器与系统依赖可正常启动。

先查目标仓库的工具链。不要用一次成功的 Python 单元测试冒充 Mermaid 或浏览器验证。正式安装方式以 [Mermaid CLI 原仓库](https://github.com/mermaid-js/mermaid-cli) 和项目约定为准。

## 命令

```bash
python3 <skill>/scripts/render_diagrams.py \
  --input docs/diagrams \
  --output docs-site/public/generated-diagrams \
  --mmdc docs-site/node_modules/.bin/mmdc \
  --timeout 60
```

以上路径是示例，按仓库实际结构替换。`--mmdc` 接受一个可执行文件路径或 PATH 中的命令名，不接受包含额外参数的 shell 命令。

输入 `docs/diagrams/orders/submit.mmd` 会生成 `docs-site/public/generated-diagrams/orders/submit.svg`。输出 JSON 记录实际生成文件与图源指纹；指纹用于比对输入版本，不证明业务正确性。

## 输出目录约定

输出目录专用于生成物。第一次运行使用不存在或为空的目录。成功后脚本写入 `.repo-diagrams-output.json`，以后依据该标记识别管理范围。

目录中出现手工文件、未知子目录、符号链接或不合法标记时，脚本停止；把手工内容移到其他位置后再运行。不要把已有站点的整个 `public/` 作为生成目录，选择独立子目录。

输入与输出不能相同，也不能互为父子目录。图源目录中的符号链接不被跟随；发现链接时停止并要求明确实际范围。相对输出保留源目录层级，同名大小写冲突会被拒绝。

## 失败行为

脚本先把所有图编译到输出目录旁的临时目录，检查产生的 XML 根节点为 SVG；任何图失败、超时、没有产物或输入中途变化，都会返回非零并保留原输出。

全部编译成功后，脚本把旧生成目录临时改名，再把新目录移入；普通的发布失败会尝试恢复旧目录。目录切换包含两次重命名，不能保证进程被强行终止或机器断电时零间隙。残留的 `.previous-…` 目录保存上一份生成物，先检查输出再恢复或清理。不要同时向同一个输出目录运行多个构建。

本工具不安装软件，不修改图源，不扫描应用代码，也不判断箭头是否符合业务实现。编译成功后仍要检查图形是否可读，以及正文、图和实际代码是否一致。

## 构建接线

将图形编译作为站点构建的前置命令，使用项目任务工具的失败传播机制。例如 Node 项目可以在 scripts 中依次执行图形构建和站点构建，并使第一步失败时停止后续步骤。

在 CI 记录实际工具版本、执行命令和结果。浏览器依赖缺失时报告具体错误；不要自动放宽环境的安全限制，也不要保留旧 SVG 后把当前构建标为成功。

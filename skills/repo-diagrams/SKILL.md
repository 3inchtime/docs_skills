# 绘制能回到代码的模块流程

把图写成具体行为的解释。先核对执行路径，再组织节点和箭头。保留图源、文字步骤与证据映射，使下一位维护者可以修改和复查。

## 接收输入并确定交付范围

1. 读取目标仓库的项目规则、指定分支或工作区状态、模块清单和已有文档站约定。
2. 优先复用调用方提供的 `docs-map.json` 与证据包。单独执行时，查找真实入口、注册关系、核心处理、配置和测试，补齐必要证据。
3. 为清单内每个模块提供至少一个具体执行流程。对纯声明、配置或基础库，说明它如何被加载、校验、转换或消费，避免给没有独立业务事务的模块编造业务流程。
4. 列出第三方、生成代码、停用模块等排除项及原因。关键证据缺失时给出具体问题，继续完成已有依据的部分。

## 先列行为，再绘图

阅读 [流程与证据规范](references/diagram-contract.md)，使用 [节点证据模板](assets/flow-evidence.template.md) 整理以下内容：

- 触发入口与允许进入流程的条件。
- 各步骤的输入、判断、读写、调用和可观察结果。
- 实际存在的拒绝、错误、超时、重试和恢复路径。
- 同步调用、异步事件、事务提交与外部系统的边界。
- 每个关键步骤对应的文件、符号、配置或测试。

打开所引用的源码。查清路由、消费者或插件是否已注册。记录配置默认值和运行时覆盖的区别。代码中没有实现的重试、补偿和状态转换，不作为现状画入图中。

## 选择合适视图

| 读者问题 | 视图 | 必须表达 |
| --- | --- | --- |
| 一次操作怎样完成或失败 | 流程图 | 入口、动作、具体条件、结果 |
| 多个模块怎样按顺序协作 | 时序图 | 参与者、调用/事件、响应、真实边界 |
| 业务对象如何变更状态 | 状态图 | 实际状态值、事件、迁移条件 |
| 数据归谁所有、怎样关联 | ER 图 | 业务实体、关系、必要约束 |
| 系统和外部依赖是什么 | 上下文或部署关系图 | 系统边界、职责、依赖 |

按需补图，不给每个模块机械套全部图种。将大图拆成一张总览和有链接的子流程，每张图回答一个明确问题。

## 编写图源和说明

1. 默认维护独立 `.mmd` 文件。为节点使用稳定英文 ID；显示标签使用业务动作，必要时附代码符号。
2. 在模块边界图上标出职责、依赖方向和实际的进程或存储边界。在运行图上复用相同的模块名，为条件边写出判断，为交接标明调用、字段或事件。保留改变数据、等待条件或失败结果的步骤；区分请求接收与业务完成。
3. 在图旁写完整的文字步骤与关键失败结果，确保搜索、打印和辅助阅读仍能获得内容。
4. 添加 `accTitle` 与 `accDescr`。同时用文字、线型或形状表达语义，不只依赖颜色。
5. 将图登记到 `docs-map.json` 的 `modules[].diagrams`，将行为证据登记到该模块的 `evidence`。具体字段见参考文档。
6. 保持一种拓扑来源：通常由 `.mmd` 生成 SVG；交互说明按节点 ID 关联。如项目已有结构化流程模型，由模型生成 `.mmd` 和交互数据，不再手工维护第二套分支。

[导出流程示例](assets/report-export.example.mmd) 是明确标注的合成示例，只展示写法与语法。依据目标仓库重写后再用于正式文档。

## 编译和发布 SVG

使用仓库已经安装并锁定版本的 Mermaid CLI。先检查项目脚本或工具清单；缺少工具时说明具体依赖，再按项目获授权的安装流程处理。此技能附带的脚本不会安装软件。

```bash
python3 <此技能目录>/scripts/render_diagrams.py --help
python3 <此技能目录>/scripts/render_diagrams.py \
  --input <仓库内图源目录> \
  --output <专用于生成SVG的目录> \
  --mmdc <项目node_modules/.bin/mmdc或已安装可执行文件>
```

脚本递归编译 `.mmd`，保持相对目录；所有图成功后才替换生成目录。任一图失败返回非零，原生成目录保持不变。非空输出目录必须有脚本的管理标记且没有额外手工文件；输入输出目录不能重叠。把该命令作为站点构建的前置步骤，失败时停止构建。参数、恢复方式与工具限制见 [编译说明](references/rendering.md)。

## 分开完成两类审查

**图形检查：**运行编译，检查缺字、遮挡、箭头、字号、长标签和窄屏表现。记录实际执行结果；只有静态阅读时明确写“未编译”。

**实现检查：**对照源码核对关键顺序、分支条件、状态变化、写入、重试次数、事务与事件位置。编译成功只证明工具能处理图源。

让没有调查上下文的读者沿图说明一个成功场景和一个失败场景，再由代码审查者核对。修复具体遗漏后定向复查。

## 交付

交付 `.mmd`、生成的 SVG、相邻文字解释、节点证据、代码版本、覆盖表和真实验证记录。代码改变时重新追踪受影响路径，同时更新正文、图源和证据；不手工修补生成 SVG 来绕过图源错误。
